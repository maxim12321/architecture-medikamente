## Наиболее критичные из потенциальных проблем

### Отсутствие тестирования (в том числе нагрузочного)

Без тестирования будет повышаться количество ошибок в релизах, что сильно
ухудшает пользовательский опыт. Такие проблемы будут задерживать разработку
новой функциональности, т.к. разработчики будут постоянно заняты исправлением
существующих багов.

Отсутствие нагрузочного тестирования приведет к тому, что снижение
производительности будет замечено только после раскатки обновлений на всех
пользоваелей.

#### Меры по устранению

1. Наладить процесс тестирования вносимых изменений.
2. Автоматизировать как можно больше тестов, чтобы из-за тестирования не
   сильно уменьшалась частота развёртывания.
3. Настроить обязательное автоматическое нагрузочное тестирование перед
   выкладкой.


### В компании единственный сервер, низкая отказоустойчивость

По требованиям, система должна стабильно работать в условиях расширения
бизнеса. Однако, пока у компании всего один сервер в офисе, это невозможно.
Масштабирование требует увеличения доступных ресурсов.

#### Меры по устранению

1. Аренда дополнительных серверов, желательно в разных ДЦ для повышения
   отказоустойчивости.
2. Дополнительно нужно правильно настроить автоматическое масштабирование в 
   Kubernetes, чтобы рост нагрузки не приводил к сбоям.


### BI-, AI-, ML-технологии ранее не использовались

Внедрение таких сложных и тяжеловесных инструментов требует как экспертизы,
отсутствующей на данный момент в компании, так и ресурсов. Важно, чтобы
при этом работа аналитических систем не влияла на производительность системы,
которую используют пользователи.

#### Меры по устранению

1. AI- и ML-технологии нужно запускать на отдельных серверах или в отдельных
   контейнерах, чтобы они не влияли на производительность остальной системы.
2. Нужно активно нанимать экспертов для работы с новыми для компании
   технологиями.


### Не настроены CI/CD процессы

Отсутствие процессов непрерывной интеграции и развертывания приведет к росту
Time to Market и в целом к задержкам в развёртывании. Особенно эта проблема
актуальна с учетом планируемого роста штата компании.

#### Меры по устранению

1. Заранее настроить CI/CD пайплайны. Можно сделать это силами администратора,
   если у него есть такая экспертиза.
2. Нужно постоянно анализировать текущие процессы, чтобы внедрять больше
   автоматизации в тестирование и развёртывание.


### Отсутствие мониторинга и алертинга

Отсутствие алертинга приведет к тому, что проблемы будут обнаруживаться только
после обращений пользователей. Это будет перегружать администраторов на
ресепшене, т.к. отдельной службы поддержки у компании нет.

#### Меры по устранению

1. Настроить сбор метрик, мониторинг и алерты. Тем более, у технического
   директора уже есть с этим опыт.
2. Возможно, стоит задуматься о создании отдела тех. поддержки, учитывая, что
   компании предстоит наращивать интеграции с партнерами.


### Интеграция с разными лабораториями может потребовать различные технологии для API

Добавление новых интеграций с различными партнерами (например, лабораториями)
через API может приводить к тому, что для разных партнеров придется делать
разные контракты.

#### Меры по устранению

1. Желательно использовать как можно более распространенные технологии.
   Например, даже если один партнер может использовать gRPC, стоит сделать
   выбор в пользу REST API.
2. Если все же потребуется добавление разных видов API, можно делать отдельные
   адаптеры, чтобы не усложнять существующий API.
