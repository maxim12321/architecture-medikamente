## Проблемные зоны

### Регистрация клиента

1. Файл Patients содержит персональные данные всех клиентов, его необходимо
   шифровать и контролировать доступ (например, только для администраторов).
2. Администратор имеет доступ ко всем пациентам с их персональными данными.
   Возможно, некоторые данные администраторам стоит  отображать в
   обфусцированном виде.

### Работа с файлами данных клиента

1. Личные каталоги пациентов содержат как персональные, так и медицинские
   данные, которые нужно шифровать.
2. Администратор имеет доступ ко всем файлам пациента (в том числе результаты
   приёмов, анализов и тд). Часть информации нужно скрывать, часть
   обфусцировать.
3. Доктор имеет доступ ко всем каталогам пациентов. Стоит предоставлять доступ
   только конкретному доктору, с которым назначен приём. Желательно даже
   ограничить доступ только на время приёма. В остальных случаях доктору
   следует выдавать временный доступ на конкретные файлы.
4. Злоумышленник может перехватить результаты анализов во время передачи по
   сети в систему Medikamente. Нужно использовать защищенные соединения,
   т.к. речь идет о медицинских данных.

### Запись пациента к доктору

1. Доктор должен иметь доступ только к своему журналу, просмотр и
   редактирование журналов других докторов должно быть недоступно.
2. Файл журнала также хранит персональные данные, нужно шифрование.

### Прием оплаты за услуги и складской учет

1. Контрольно-кассовая машина передает данные о транзакциях по сети. Необходимо
   использовать защищенное соединение, чтобы избежать перехвата данных.
2. Бухгалтеру нужна ограниченная информация о транзакциях, остальное нужно
   показывать в обфусцированном или обезличенном виде.
3. Данные о транзакциях и ТМЦ также необходимо шифровать, хоть это и не
   персональные данные, но все равно они конфиденциальны.

## Список данных и способ их защиты

Способы защиты также отражены на диаграмме потоков данных.

|**Данные**|**Способ защиты**|
|-|-|
| Персональные данные пациента | Шифрование при хранении; <br> Обфускация лишних данных при просмотре; |
| Медицинские данные клиента | Шифрование при хранении; <br> Обфускация при просмотре (для некоторых ролей); |
| Результаты анализов | Шифрование при хранении и передаче; <br> Доступ только доктору на время приёма; |
| Журнал записи | Шифрование при хранении; |
| Платежные транзакции | Шифрование при хранении и передаче; <br> Обезличивание для бухгалтерии; |
| Данные о ТМЦ | Шифрование при хранении; |

## Тегирование

Так как данные хранятся в виде файлов (в основном Excel), можно использовать
Microsoft Azure Information Protection для тегирования данных на основе
классицикации при их обнаружении. Это будет особенно полезно, учитывая что
в системе есть коммуникация через электронную почту, где письма также
могут содержать конфиденциальную информацию.

Также, можно будет раньше настроить доступ на основе этих тегов, тем самым
уменьшить риски еще до реализации финальной версии системы.
